# CI-node notes

This repository gets a machine to the point where CI software can be installed cleanly. The CI layer should stay replaceable.

## Host OS

Use **Ubuntu 26.04 LTS** natively on the REDMI Book.

The useful baseline is:

- x86-64 Linux;
- native ext4 project/build storage;
- 32 GB RAM;
- local NVMe;
- current kernel/firmware support;
- SSH available for administration.

Do not add an Ubuntu 24.04 container simply because `ubuntu-latest` currently maps to 24.04. Use a different userspace/container only when a specific compatibility test actually requires it.

## GitHub Actions

A self-hosted runner is registered with a short-lived token generated by GitHub. **Never commit that token**.

Useful labels for this machine might include:

```text
self-hosted
linux
x64
redmi
255h
```

Keep hardware/capability labels descriptive enough that a scheduler can select the node without encoding its physical location.

A normal GitHub self-hosted runner process executes one job at a time. If we want multiple simultaneous jobs, we can deliberately run multiple runner instances or let a higher-level executor (for example Glaeda) partition the machine.

## What to benchmark after install

Before tuning anything, record a baseline:

1. `git clean` / dependency-materialization filesystem benchmark;
2. representative clean build;
3. representative incremental build;
4. representative unit/integration test suite;
5. two or more jobs concurrently;
6. sustained CPU temperature/power behavior;
7. NVMe free space and cache growth.

That tells us how many useful CI slots the laptop actually has instead of inferring them from core count.

## Filesystem

Start with the Ubuntu installer's ordinary **ext4** root filesystem.

That gives us a boring native-Linux baseline and directly exercises the filesystem semantics that motivated buying/using a Linux node in the first place. Add XFS/btrfs/OverlayFS/reflink experiments only after the baseline is measured.

## Sleep and laptop-specific tuning

Do this after remote management works:

- no automatic suspend while on AC;
- lid close suspends as the unambiguous family/transport safety action; leave the machine physically open while it is acting as a node;
- 70–80% charge ceiling;
- reboot test after every persistent power-management change.

The REDMI Book Pro 16 2025 has documented Linux charge-limit support. See the machine guide's ArchWiki link.

## GitHub hosted-image parity

OS version is only one part of hosted-runner parity. GitHub's runner images also contain a large preinstalled toolset and image-specific configuration.

For projects that need reproducibility, prefer one of these explicit approaches:

- pin the project's toolchains and dependencies;
- use a project-defined container/image;
- run the same bootstrap script on hosted and owned runners;
- test both environments when the difference itself is meaningful.

The host should remain a current, well-supported Linux machine rather than becoming a clone of one particular hosted image snapshot.
